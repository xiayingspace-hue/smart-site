# 角色定义（跨端共享）

> **本文档是全项目角色的单一事实源**。所有需求与下游文档（UI / 前端 / 后端 / QA）
> 涉及角色时，必须使用本文档 §1 的标准名，并遵守 §2 的禁用词表。
>
> 本文档不属于任何单个 REQ，故不采用 `REQ-{编号}-shared.md` 命名。

## 1. 角色标准名

> **图纸线判定规则**：凡图纸相关需求（REQ-003x / 004 / 005 / 007x / 003-app）中
> 出现的「管理员」，一律指**图纸管理员**，不是项目级或平台级管理员。
>
> **关于 ROLE-XXX 编号**：各需求文件 §4.1 中的 `ROLE-XXX` 是**文件内局部编号**，
> 同一编号在不同需求中含义不同（如 `ROLE-001` 在 16 份文件中代表 10 种角色）。
> 跨文档引用角色时**必须使用下表的标准名，不要使用 ROLE-XXX 编号**。

### 1.1 图纸线角色

| 标准名 | 英文 / 代码 | 定义 | 关键权限 |
|-------|------------|------|---------|
| 设计人员 | Designer | 图纸上传人,拥有发布/删除权限 | 上传图纸、发布 Part Print |
| 图纸管理员 | DrawingAdmin | 负责图纸域的配置与分配 | `drawing:area-config`、`drawing:dc-config`、SE 分配 |
| 内部审批人 | InternalApprover | 一级审批(内部) | 内部审批 Todo 处理 |
| Document Controller | DC | 二级审批(外部) | 外部审批标记 |
| Site Engineer | SE | 现场查阅图纸,不访问 PC 管理端 | 查看已生效版本 |
| 免审批上传人 | — | 上传已完成审批的图纸,直接生效 | 免审批上传(REQ-003H 专有) |
| 普通用户 | — | 无任何图纸域权限 | 无 |

## 2. 角色禁用词

### 2.1 图纸线角色名

| ❌ 不要用 | ✅ 应该用 | 原因 |
|---------|---------|------|
| 项目管理员 | 图纸管理员 | 图纸线中不存在"项目级"管理员,职责全部落在 `drawing:` 权限域 |
| 项目管理人员 | 图纸管理员 | 同上;与"项目管理员"是同一角色的两种写法 |
| 管理员 | 图纸管理员 | 裸用"管理员"在图纸线中一律指图纸管理员,应写全 |
| 管理员 / Drawing 团队 | 图纸管理员 + 设计人员 | 这是两个角色合并成的权限矩阵列,应拆成两列而非当作一个角色 |
| 业务人员 | 图纸管理员 | ⚠️ 高危:此处"业务人员"指**有** `drawing:dc-config` 权限的人,与"普通业务人员"含义相反 |
| Drawing 团队成员 | 设计人员 | 权限矩阵同构位置可证为同一角色 |
| 审批人 | 内部审批人 | 需与外部审批(DC)区分,不可省略"内部" |
| Approver（审批人员） | 内部审批人 | 同上 |
| 普通业务人员 | 普通用户 | ⚠️ 高危:易与"业务人员"混淆,而两者含义相反 |
| Admin | 图纸管理员 | 图纸线中 `Admin` 指图纸管理员(REQ-005) |

> ⚠️ **最高危的一对**:「业务人员」= 有图纸管理权限;「普通业务人员」= 无任何图纸权限。
> 两词仅差"普通"二字而含义相反,已全部禁用,分别改写为「图纸管理员」和「普通用户」。

> 角色名中的括号统一用全角 `（）`，见 `rules/global-rules.md` §9.1。

### 2.2 非角色名的限定写法

以下写法出现在权限矩阵列头,是**同一角色的状态限定**,不是独立角色,不需登记为角色：

| 写法 | 实为 |
|-----|------|
| DC（已配置）/ DC 自身 | Document Controller |
| 内部审批人（本人）/（他人） | 内部审批人 |
| 设计人员（本图纸上传人） | 设计人员 |
